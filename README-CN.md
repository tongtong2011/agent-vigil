# agent-vigil（AgentVigil · Agent任务看板与监控）

非官方 · 免费 · 开源

通过电脑端 Node.js 桥接服务，把电脑上**多个 AI Agent 工具（harness）**的任务聚合成一个手机看板（PWA）：
查看任务列表与内容（与电脑端一致的对话式视图），并可在手机上**直接给 AI 任务发消息**（确认、纠偏、补充要求）。
支持**公网访问**（Cloudflare 免费隧道）、**配对信息邮箱推送**与**任务告警/定时汇总邮件**——人不在电脑旁也能掌控任务。
一套代码覆盖 Android / iOS / 鸿蒙，无需上架。

> **免责声明**：本项目为个人学习研究用途的互操作工具，与爱思办公官方无关。
> 实现依赖非官方接口，可能随时失效；请仅使用自己的账号、自己的邮箱等外部服务配置。
> 官方若推出手机版，本项目即完成使命。

## 功能

| 编号 | 功能 | 说明 |
| --- | --- | --- |
| FR1 | 连接配对 | 电脑端展示二维码（地址 + 配对码，码在有效期内可重复使用），手机扫码或手动输入完成配对，下次自动连接 |
| FR2 | 任务列表 | 按创建时间倒序展示标题 / 状态（进行中·已完成·失败）/ 时间，支持下拉刷新 |
| FR3 | 任务详情（对话视图） | 与电脑端一致：用户消息右气泡、AI 回复左气泡（Markdown 渲染：表格 / 加粗 / 代码块），底部模型名与时间 |
| FR4 | 处理过程折叠 | 每条 AI 回复下方的工具调用折叠为「已处理 N 步」胶囊，默认收起；含失败步骤时红色提示 |
| FR5 | 实时刷新 | WebSocket 事件驱动（任务有变化才拉取）+ 8 秒兜底轮询；断线指数退避重连；内容无变化不重渲染 |
| FR6 | 手机发消息（V2） | 详情页底部输入栏，任务报错或等待确认时直接回复「同意执行」「改用方案 B」等；限速保护 |
| FR7 | 公网访问（V2） | 自动拉起 Cloudflare 免费隧道（免账号免域名），手机任何网络可访问；断线自动重连 |
| FR8 | 配对信息推送（V2） | 配对码/公网地址有变动时，自动把地址+配对码+二维码**推送到你的邮箱**（邮件带服务器发送时间与「第 N 次生成」计数，与页面/控制台对应；失败自动重试）（企业微信可选） |
| FR9 | 配置向导（V2） | 首次启动分步引导配置邮箱/隧道/配对策略，保存立即生效（仅限本机访问） |
| FR10 | 手机远程配置（V2） | 推送邮件带第二个区块（链接+二维码）：手机扫码可**改收件邮箱 / 切换发件配置档案 / 发测试邮件**（令牌鉴权，敏感操作仍限本机向导） |
| FR11 | 发件配置自动故障转移（V2） | 保存 ≥2 份发件档案时，当前 SMTP 连续 2 次发送失败自动切换下一份并立即重试——多套配置指向同一收件箱，哪套活着推送都能送达 |
| FR12 | 任务两级分组（V2） | 首页按任务工作目录显示为「文件夹 → 任务」两级（与电脑端一致）：默认只显示文件夹，逐个点开或顶栏「全部展开/收起」 |
| FR13 | 任务告警与定时统计（V3） | 详情页「🔔 追踪」标记要监控的任务（存手机本地，重开保持）；「单任务报警」总开关/标题前缀与「任务汇总」总开关/间隔/标题均在配置中心配置 → 被追踪任务出现异常或待确认（阻塞）且报警总开关打开时立即发单任务提醒邮件；按间隔把被追踪任务汇总成表格邮件；邮件复用现有发件服务与收件人 |
| FR14 | 多渠道统一看板（V4） | 列表页顶置渠道 Tab（健康状态点），点击切换各 harness 的任务列表；仅接入一个渠道时不显示 Tab；服务端快照预热 + 按渠道缓存，切 Tab 秒显；列表条数上限可配（默认 100） |
| FR15 | 渠道级配置 + Tab 式配置中心（V4） | 渠道启停用勾选；「任务汇总/单任务报警开关、标题前缀」按渠道独立配，「汇总间隔、汇总标题、看板列表条数上限」全渠道统一配；配置中心 6 页签（首页总览/邮箱推送/公网访问/公共配置/渠道独立配置/看板与配对），每页独立保存即时生效 |
| FR16 | 多渠道邮件合并与来源标注（V4） | 各渠道汇总合并为**一封**邮件、按渠道分节；单任务报警邮件标注「来源渠道」；停用渠道自动隔离；旧 config.json 自动迁移 |

**内置渠道**：爱思办公（ACP，可发消息）/ WorkBuddy（本地转录直读 + 进程门禁，V4.1 起可发消息）/ Trae（记忆转录直读，只读）。
新增 harness 只需实现 `lib/adapters/base.js` 接口并注册到 `lib/adapters/index.js`。

数据**恒来自各渠道对应 harness 的本地真实数据**，没有演示/假数据机制——某渠道数据源不可用时该渠道看板为空，并在启动日志、推送邮件、手机看板顶部三处醒目提示，恢复后自动跟上。

## 启动前置条件（务必先读）

> ⚠️ **看板的数据来自各渠道对应的本地 Agent 工具**——至少要有**一个**已接入的 Agent 工具在运行，看板才有数据；都没运行就是空看板，不会显示任何演示假数据。

| # | 前置条件 | 说明 |
| --- | --- | --- |
| 1 | **Node.js ≥ 18**（建议 LTS） | https://nodejs.org 下载安装，一路下一步 |
| 2 | **想看的渠道对应的电脑端工具在运行** | 爱思办公：桌面端登录并保持运行（自动发现 agnesd 端口与密钥）；WorkBuddy：桌面端运行（本地转录直读 + 进程门禁）；Trae：IDE 使用中（读记忆子系统转录） |
| 3 | **联网** | 首次 `npm install` 装依赖；cloudflared 未安装时首次启动自动从 Cloudflare 官方下载（约 18MB，放入项目 `tools/`） |
| 4 | 手机端无需安装任何 App | 浏览器打开即用（可选「添加到主屏幕」变 PWA） |

**未满足前置条件时的行为**（服务照常启动，绝不崩溃）：

- 启动日志：醒目警告框（各渠道有对应提示，如「⚠ 未检测到爱思办公（agnesd）本地服务……」）
- 推送邮件：合并汇总邮件内附加红色「数据源不可用」警告节，并附配置中心 `http://127.0.0.1:8787/setup.html` 链接（该页仅限电脑端打开）
- 手机看板：对应渠道 Tab 顶部置顶提示条（如「未检测到爱思办公进程，取不到任务数据」），工具启动后自动消失

### 部署启动（3 步）

1. **下载解压**：GitHub Releases 下载 `agent-vigil-VX.Y.Z.zip`（或 `git clone` 本仓库），解压到任意目录
2. **双击 `启动服务.bat`**：首次运行自动安装依赖（需联网，约 1~2 分钟），之后自动启动桥接服务；习惯命令行的话也可 `npm install` 后 `node bridge.js`
3. **完成配置中心**：按控制台提示打开 `http://127.0.0.1:8787/setup.html`（仅限本机电脑），6 页签 Tab 式配置中心：

```
首页（状态总览 + 连接手机二维码）→ 邮箱推送（选服务商 → 填授权码 → 发测试邮件；可存档案）
→ 公网访问（自动检测，免注册；支持命名隧道固定域名）→ 公共配置（汇总间隔 + 汇总标题）
→ 渠道独立配置（渠道勾选启停 + 各渠道汇总/报警开关与前缀）→ 看板与配对（配对码有效期 + 列表条数上限）
```

每个页签底部独立保存、保存即生效。配置完成后，连接信息（地址 + 配对码 + 二维码）会自动发一封邮件到你邮箱，以后有变动也会自动重推。

### 手机连接

1. 打开电脑端控制台显示的**地址**，或用手机扫描二维码 / 打开推送邮件里的链接（配置推送后，人在外面也能收到新地址新码）。
2. 手机与电脑同一 WiFi 时用局域网地址即可；配好隧道后用公网地址，任何网络可用。
3. 输入 6 位配对码 → 连接成功后进入任务列表。
4. （可选）通过浏览器菜单「添加到主屏幕」安装为 PWA 应用。

桥接服务重启后设备配对会失效，需重新扫码/输入配对码（安全设计：配对码只存内存）；
已配置邮箱推送时，新配对码会自动发到你邮箱，不用跑回电脑旁看。

### 日常使用注意

- **电脑保持开机**：桥接服务窗口、爱思办公电脑端都要开着（关闭黑窗口 = 停止服务）
- **电脑休眠/断网** 手机就连不上——建议在电源设置里把「睡眠」改为「从不」（或接电源时永不休眠）
- 爱思办公重启没关系：桥接会自动重新发现它的端口与密钥；桥接服务重启才需要重新配对

## 邮箱推送配置指引（获取 SMTP 授权码）

在配置向导第 2 步（或直接编辑 `config.json` 的 `mailer` 段）填写。**授权码不是邮箱登录密码**：

| 邮箱 | 开通路径 |
| --- | --- |
| **QQ 邮箱** | 网页版 → 设置 → 账号 → 「POP3/IMAP/SMTP…服务」→ 开启「SMTP 服务」→ 按提示发短信 → 生成 16 位授权码 |
| **163 / 126** | 网页版 → 设置 → POP3/SMTP/IMAP → 开启「IMAP/SMTP 服务」→ 弹窗设置「授权码」（会发送短信确认） |
| **Gmail** | 需先开启两步验证 → Google 账号 → 安全 → 「应用专用密码」生成 16 位密码 |

- SMTP 服务器与端口：QQ `smtp.qq.com:465`、163 `smtp.163.com:465`、126 `smtp.126.com:465`、Gmail `smtp.gmail.com:465`（均 SSL）；向导里选服务商会自动填
- 收件邮箱填**自己的邮箱**即可（自己发给自己）；也支持**逗号分隔多个地址**群发（中英文逗号均可，自动去空去重，单个地址被对方服务器拒收不影响其余收件人）
- 填完先点向导里的「**发送测试邮件**」验证，成功后保存即生效
- **个别非标服务商（如 2925.com）**：要求发件地址必须是授权身份之一（通常是手机号别名），登录邮箱发不出去。向导「高级 → 发件地址」填入提示中列出的身份即可（测试邮件失败时会自动给出可填的地址）
- **多家发件邮箱切换（发件配置档案）**：配置好并测试成功后点「💾 保存当前为档案」命名保存；之后换服务商整段重填即可，或从「📁 已保存的发件配置」下拉选择一键应用。「↺ 重置发件配置」只清发件配置，**收件邮箱与已保存档案不受影响**。档案（含授权码）只存本机 `config.json`，页面只显示掩码
- 授权码只存在你自己电脑的 `config.json`，随时可在邮箱设置里撤销

## 接口

`GET /health`（健康检查，含 `channels` 各渠道在线汇总）、`GET /api/tasks?channel=`（任务列表，缺省 agnes）、`GET /api/tasks/:id?channel=`（任务详情）、`POST /api/tasks/:id/messages`（发消息，V2；只读渠道如 Trae 返回 501），均需请求头 `X-Device-Token`（配对成功时返回，手机端自动携带）。
配置中心接口 `GET/POST /api/setup/*` **仅允许本机 127.0.0.1 访问**（远程一律 403）。

## 配置说明（config.json）

| 字段 | 说明 |
| --- | --- |
| `listenHost` / `port` | 监听地址与端口，默认 `0.0.0.0:8787` |
| `acp.autoDiscover` | `true`（默认）= 自动发现 agnesd 端口并从进程内存读取密钥 |
| `acp.port` / `acp.secret` | 自动发现失败时手动指定（agnesd 重启后端口/密钥会变，建议保留自动发现） |
| `official.*` | 预留的 HTTP 直连配置（占位符，未使用） |
| `timeoutMs` / `pollIntervalMs` | 网络超时（5000ms）/ 变化检测轮询间隔（3000ms） |
| `tunnel.enabled` | V2：公网隧道开关（默认 `true`；cloudflared 未安装时首次启动自动下载，失败才降级纯局域网） |
| `tunnel.cloudflaredPath` | cloudflared 路径；留空 = 依次找项目 `tools/`（首次启动自动下载到这）→ PATH |
| `pair.codeTtlMinutes` | V2：配对码有效期（分钟），5~120，默认 15（V3 起向导不再提供此配置，改 config.json） |
| `messages.enabled` | V2：手机发消息开关（默认 `true`；V3 起向导不再提供此配置——默认允许发消息，改 config.json 可关） |
| `alerts.*` | V3：任务告警（`digestIntervalMinutes` = 汇总间隔分钟（10~240 默认 60）、`digestTitle` = 汇总邮件标题（默认「任务汇总邮件」）——V4 起全渠道统一；`digestEnabled`/`alertEnabled`/`alertPrefix` = agnes 渠道旧生效源回退，各渠道显式配置在 `channels.<ch>`；`watchlist` = 追踪清单的手机端同步副本（`{channel, taskId}` 二元组），源头在手机端 localStorage、变化时自动写回，桥接重启从本文件恢复） |
| `board.listLimit` | V4.1：看板任务列表条数上限，**全渠道统一**（按最近更新倒序截断；下限 100，默认 100）。配置中心「看板与配对」页签滑块可调（100 ~ `listLimitMax`）；也可手改本键为任意值，保存即热生效 |
| `board.listLimitMax` | V4.1：滑块允许的最大值（默认 1000）。手改本键后重新打开配置中心，滑块范围自动扩展；不设上限强制 |
| `channels.<ch>` | V4：渠道配置（`ch` ∈ `agnes` / `workbuddy` / `trae`）：`enabled` = 渠道启停（false = 不初始化、Tab 不显示、告警忽略）；`alertEnabled`/`digestEnabled`/`alertPrefix` = 该渠道单任务报警/任务汇总开关与报警标题前缀（默认关）；未知渠道键前向兼容保留，渠道级旧键自动清洗 |
| `mailer.*` | V2：邮箱推送（`smtpHost/smtpPort/smtpSecure/user/pass/to`；`from` 可选=发件地址别名，留空同登录邮箱；`to` = 收件邮箱，V3 起支持逗号分隔多个、自动归一化存储；`saved` = 已保存的发件配置档案数组（含授权码，仅存本机，供向导一键切换/重置，≥2 份时发送连续失败自动故障转移）；`toHistory` = 收件邮箱历史（远程配置页下拉快选，最多 10 条）；留空 mailer 整段 = 关闭） |
| `wecom.*` | V2：企业微信推送（可选；`corpId/corpSecret/agentId/toUser`；留空 = 关闭） |
| `setup.done` | 配置向导是否已完成（完成后启动不再弹提示） |

### 数据来源与访问边界

- **爱思办公（agnes 渠道）**：通过其内置本地 AI 后端 `agnesd`（goose 框架）读取：`session/list` 拉任务（会话）列表，`session/load` 重放会话历史聚合成对话内容；WebSocket 长连接实时订阅变化。端口从日志自动发现；密钥由 `lib/get-agnes-secret.ps1` 从进程内存读取（随机生成、不落盘），绝不下发手机端。
- **WorkBuddy / Trae（V4 文件直读渠道）**：适配器只读本地转录文件（WorkBuddy 数据根 `~/.workbuddy`；Trae 为记忆子系统转录 JSONL），带进程门禁（应用不在 = 渠道无数据、看板清零）。均为本地文件读取，不调用网络接口。
- **默认只读**：对 agnesd 仅调用 `initialize` / `session/list` / `session/load`；WorkBuddy/Trae 转录文件只读不写。唯一写方法例外是手机发消息（agnes 走 `session/prompt`；WorkBuddy V4.1 起 headless CLI 续聊回写），须配对设备令牌触发、限速、可在配置中关闭；Trae 无注入通道，发消息返回 501。

## 项目结构

```
project/
  bridge.js              # 桥接服务入口（静态托管、适配器装配、渠道启停热应用、推送调度、向导集成）
  启动服务.bat           # Windows 双击启动（保持控制台窗口可见）
  lib/
    adapters/            # V4 多渠道适配器（base.js 统一接口 + agnes/workbuddy/trae 实现 + index.js 注册表工厂/快照预热）
    channels.js          # V4 渠道策略单一真源（渠道生效配置、agnes 旧键回退、watchlist 二元组归一）
    official.js          # agnes 数据聚合客户端（ACP 会话→对话回合聚合 + 发消息；mock 演示机制已移除）
    acp.js               # ACP 客户端（自动发现、WS 订阅、session/load、session/prompt）
    get-agnes-secret.ps1 # 从 agnesd 进程内存读取密钥（随机生成不落盘）
    localApi.js          # 本地 HTTP API（任务/详情/发消息 + 配对限速，支持 ?channel=）
    setupApi.js          # Tab 式配置中心 API（仅限本机；白名单保存/测试邮件/热应用）
    remoteApi.js         # V2 手机远程配置 API（邮件令牌；改收件人/切发件档案/测试邮件/告警与汇总开关）
    smtp.js              # V2 轻量 SMTP 客户端（SSL/STARTTLS、发件别名、优雅收尾）
    wsHub.js             # WebSocket 推送（/ws，令牌校验 + 心跳）
    pair.js              # 二维码配对（配对码 → 设备令牌；TTL 内可复用，可配置）
    tunnel.js            # V2 Cloudflare 隧道管理（URL 解析、断线重连、降级）
    mailer.js            # V2 邮箱 SMTP 推送（HTML 内嵌二维码；V4 合并汇总 sendDigestAll）
    wecom.js             # V2 企业微信推送（可选）
    config.js            # 配置加载 + 保存（V4 自动迁移 + 渠道键清洗）
  web/
    index.html           # 手机端 PWA 单页（渠道 Tab / 连接页 / 列表页 / 详情页 + 发消息输入栏）
```

## 常见问题

- **看板是空的**：99% 是对应的 Agent 工具没在运行——看板顶部有橙色提示条时，回电脑启动对应工具即可，桥接自动重连出数据（无需重启）；若刚部署还没配，先在电脑端打开 `http://127.0.0.1:8787/setup.html` 完成配置。
- **手机打不开地址**：手机与电脑在同一 WiFi 时用局域网地址（Windows 首次运行需在防火墙放行 Node.js）；不在同一网络时用公网隧道地址（向导里开启）。
- **提示配对码无效**：配对码过期（默认 15 分钟）或已使用；服务会在过期后 60 秒内自动发新码（已配置推送时直接进邮箱），也可重启服务立即获取。
- **收不到推送邮件**：①先在向导里点「发送测试邮件」排查（多数是授权码填错或端口不对）；②检查手机邮件 App 的垃圾邮件箱；③确认邮件 App 开了通知。
- **公网地址打不开**：快速隧道地址随重启变化，以最新推送/控制台为准；Cloudflare 偶发首次建连慢，重试即可。
- **固定域名（命名隧道）配置完打不开**：公网链路共三段，按报错逐段排查——
  1. **域名解析不出（浏览器提示 DNS 错误）**：Cloudflare 上缺 CNAME 记录。到 DNS 面板加：类型 `CNAME`、名称 `@`（或你的子域）、目标 `<隧道ID>.cfargotunnel.com`（隧道 ID 在 Tunnels 页面可见）、**代理状态打开（橙色云）**。
  2. **报 503**：流量已进隧道但没有路由规则（ingress）。到 [one.dash.cloudflare.com](https://one.dash.cloudflare.com) → Networks → Tunnels → 点你的隧道 → **Public Hostname** → Add a public hostname：Domain 选你的域名，Service 类型选 **HTTP**、URL 填 `localhost:8787`。这是手工配置最容易漏的一步——**只建隧道+加 CNAME 不够，没有 Public Hostname 必定 503**。
  3. **本机服务没起**：电脑上执行 `curl http://127.0.0.1:8787/health`，不返回 ok 就是桥接没在跑。
  - 推荐直接用配置向导第 3 步「固定域名（正式）」的**初始化按钮**：自检式幂等——同名隧道已存在就复用、CNAME 缺失/指向不对自动补、路由规则缺失自动写，不管你手工弄了一半还是全没弄，点一次就收敛到正确状态。
  - 初始化报错对照：`Authentication error` / `获取隧道运行令牌失败` = API 令牌权限不足（需「账户 · Cloudflare Tunnel · 编辑」+「区域 · DNS · 编辑」）；`未在该账号找到 zone` = 域名未托管到该 Cloudflare 账号或 NS 还没生效（最长数小时）；`unknown variant` = 旧版本代码 bug，更新代码重试。
  - API 令牌创建：dash.cloudflare.com → 右上角头像 → 我的个人资料 → API 令牌 → 创建令牌（自定义令牌，按上面权限勾选）；令牌只在初始化时用一次，不保存。
- **想完全手工配置命名隧道**：Zero Trust 仪表盘建隧道（Networks → Tunnels → Create a tunnel）→ Public Hostname 绑域名和 `localhost:8787`（会自动建 CNAME 和路由规则）→ 把运行令牌填进本机 `config.json` 的 `tunnel.tunnelToken`，并设 `tunnel.mode: "named"`、`tunnel.hostname: 你的域名`，重启桥接。
- **发消息提示失败/无回复**：消息送达即返回成功，AI 处理需要时间（复杂任务数分钟），回复实时出现在对话流；若限速（每分钟 10 条）会提示 429，稍等即可。
- **提示配对已失效**：桥接服务重启会清空设备令牌，重新扫码配对即可（新码已推送到邮箱）。
- **手机界面是旧版**：下拉刷新 1~2 次即可（Service Worker 后台自动更新，仅首次需要）。
- **电脑端任务偶发标红「被锁」**：手机查看详情需向爱思办公本地后端加载一次会话，偶发红点属正常现象，电脑端点开该任务即恢复，不影响功能。详见 `CHANGELOG.md` V1 变动二。
- **进行中任务的延迟**：AI 正在执行时手机端约 3~5 秒刷新一次。
- **爱思办公重启后**：桥接自动重连（端口/密钥会变，自动发现机制会重新获取）。
- **顶栏显示「轮询中」**：WebSocket 暂不可用，已自动降级轮询，恢复后自动切回「实时」。
- **离线**：展示最后缓存的任务列表。

## 安全与合规

- **默认只读**：对爱思办公仅做读取；唯一的写操作是 V2 手机发消息（须配对令牌 + 限速 + 可关闭），不创建任务、不删除任何东西。
- agnesd 密钥只存在于电脑端内存；手机端仅持有桥接配对签发的设备令牌。
- 配对码在有效期内可重复使用（多设备可先后配对）、到期自动换新推送，有效期可配（5~120 分钟）；配对接口限速防爆破；发消息接口限速。
- 公网隧道流量经 Cloudflare 加密中转；**配置向导仅限本机 127.0.0.1 访问**，SMTP 授权码等凭据永不回传前端、只存本机 `config.json`。
- 所有外部服务（邮箱/企业微信/隧道）均使用部署者自己的账号，项目本身不内嵌任何第三方账号，不经任何第三方服务器中转。
- 中性命名、不打包官方素材；以 MIT 许可开源（见各设计文档的合规策略）。
