# 项目开发指令 · agent-vigil（Trae Solo Build 模式）

> 使用方式：把本文件全文复制为 Trae Solo Build 的第一个提示词。项目根目录下放置四份设计文档（建议提供 .md 版本，Trae 读取更稳定），命名如下。Solo 模式下请按本指令自主完成，不要中途向用户提问，使用合理默认值推进。

---

## 一、项目目标

构建「agent-vigil」的 **MVP 实验版**：一个非官方、免费、开源的跨平台手机端 Web 应用（PWA），通过「电脑端 Node.js 桥接服务」以**只读**方式查看电脑上爱思办公的任务列表、最新任务、任务进度与 AI 执行步骤明细。

- 非官方：不依赖官方授权，对官方接口做只读调用（本版本以 mock 代替真实调用，真实接口留占位）。
- 跨平台：一套代码覆盖 Android / iOS / 鸿蒙，通过手机浏览器访问。
- 只读：仅查看任务信息，绝不创建、修改、删除任务。
- 成本最低、功能最简、最快上线。

## 三、技术栈（必须遵守，不得自行更换）

| 部分 | 选型 | 说明 |
|---|---|---|
| 桥接服务 | Node.js（≥18）+ Express + ws | 轻量、本地运行 |
| 实时推送 | WebSocket（ws） | 实时刷新；降级轮询 2~5 秒 |
| 手机端 | 单页 PWA（纯 HTML/CSS/JS，无框架） | 一套代码全平台 |
| 配对 | 二维码（qrcode 库） | 扫码连接，免输入 IP |
| 界面语言 | 简体中文 | 移动端优先布局 |

不要引入数据库、构建工具链、复杂框架或测试框架，保持最小可运行。

## 五、必须实现的功能（MVP，全部只读）

- **FR1 连接配对**：桥接启动后生成二维码（内容为 URL，含地址与一次性配对码）；手机扫码解析并完成配对，配对码一次性有效，连接成功保存到手机本地存储，下次自动连接。
- **FR2 任务列表**：本地接口 `GET /api/tasks`，返回任务列表，按创建时间倒序（最新在前）；每项含标题、状态（running/done/failed）、进度。
- **FR3 任务详情**：`GET /api/tasks/:id`，返回单个任务完整信息（含步骤）。
- **FR4 步骤明细**：详情中展示 AI 执行步骤，每步含名称、状态、输出摘要。
- **FR5 实时刷新**：WebSocket 推送 `task_update`、`step_update`；手机端断线指数退避重连；若推送不可用则降级为轮询。
- **健康检查**：`GET /health` 返回 200。

## 六、数据模型（按详细设计 4.1）

```json
{
  "id": "任务ID",
  "title": "任务标题",
  "status": "running | done | failed",
  "progress": 0,
  "createdAt": "ISO时间",
  "steps": [
    { "name": "步骤名", "status": "running | done | failed", "output": "输出摘要" }
  ]
}
```

## 七、严格约束（违反即不合格）

1. **禁止编造官方接口**：官方 API 主机、token、复刻请求头一律使用 `config.json` 中的占位符（如 `<API_HOST>`、`<TOKEN>`），不得编造真实地址或尝试访问真实官方服务。
2. **mock 优先**：`lib/official.js` 实现为 mock 客户端，内置 2~3 条示例任务（含进行中、完成、失败状态），使无官方凭证时也能完整演示全流程；同时在代码注释中写明「Phase 0 抓包后替换为真实接口」的映射说明。
3. **只读铁律**：桥接服务对官方调用仅做读取，不实现任何写操作、登录注册、通知推送、多账号。
4. **token 归属**：token 只存在于电脑端 `config.json`，绝不写入或下发给手机端。
5. **界面中文、移动端优先**，可添加到主屏（manifest 配置齐全）。

## 八、完成标准（Definition of Done）

- [ ] `npm install` 后 `node bridge.js` 可启动，`/health` 返回 200。
- [ ] 使用内置 mock 数据可完整演示：手机扫码连接 → 任务列表 → 任务详情 → 步骤明细 → WebSocket 实时更新。
- [ ] 模拟一个任务步骤状态变化时，WebSocket 能向手机端推送更新，界面无需刷新可见变化。
- [ ] `web/manifest.json` 有效，`index.html` 在手机浏览器（Android/iOS/鸿蒙）可访问并添加主屏。
- [ ] 代码含基本错误处理与超时（网络超时默认 5 秒，可配置），桥接对官方调用失败做降级、不崩溃。
- [ ] `README.md` 写明：如何运行、如何在同一 WiFi 用手机访问（电脑IP:8787）、Phase 0 抓包后如何填写 `config.json`。
- [ ] 全项目不出现任何真实或编造的官方接口地址。

## 九、验证方式（完成后自查）

1. 启动桥接服务，用 `curl` 依次验证 `/health`、`/api/tasks`、`/api/tasks/:id`。
2. 用浏览器打开 `web/index.html`（或由桥接服务托管静态页面），确认手机端 UI 可用、扫码/输入地址可连接。
3. 手动触发 mock 数据中一个步骤状态变化，确认 WebSocket 推送生效。
4. 逐项核对第八节完成标准，全部满足才算完成。

## 十、明确不做（超出即为越界）

- 不做真实官方对接（只留占位 + mock）。
- 不做 Phase 2 隧道（远程随时随地版），本期仅局域网。
- 不做应用上架、多账号、写操作、通知推送、历史归档。
- 不引入数据库、复杂框架、CI 或构建工具链。
