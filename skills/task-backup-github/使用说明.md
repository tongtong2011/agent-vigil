# task-backup-github · 使用文档

一键备份当前任务到 GitHub 私有仓库的 Skill（多平台适配：爱思办公 / WorkBuddy / 豆包 / Trae，各平台备份目录自动隔离）。

## 1. 前置条件

### 1.1 GitHub 账号与仓库
- 拥有 GitHub 账号（示例用户名 `tongtong2011`）
- 新建一个**私有仓库**：`ai-workspace-backup`（名字沿用即可，可改）
- 地址：`https://github.com/<你的用户名>/ai-workspace-backup`

### 1.2 创建该仓库专属的 token（发给 Skill 使用）
在该仓库 **Settings → Developer** 里创建 **Fine-grained token**（最小权限，推荐）：

| 项 | 设置 |
|---|---|
| Repository access | **只选本备份仓库**（如 `tongtong2011/ai-workspace-backup`） |
| Permissions | 只勾 **Contents: Read and write**，其余一律不勾 |

> 该 token 交给本 Skill 后，由 Skill 用它完成上下文日志与输入输出备份（git push）。
> **安全要求**：token 只写入 Windows 凭据管理器（见 1.5），严禁明文存储、严禁出现在任何备份文件/git 历史中。

### 1.3 本地环境
| 工具 | 版本要求 | 说明 |
|---|---|---|
| Git | 2.x+ | 需 `git credential manager`（Windows 默认自带） |
| Node.js | **v18+** | 仅 MCP 服务需要；PATH 中的 `node` 可能是旧版，需用 v18+ 的绝对路径 |
| Windows 凭据管理器 | 系统自带 | PAT 存这里，git push 自动鉴权，不落明文 |

### 1.4 首次初始化：本地目录结构（每个平台一个一级目录）

> **前提**：备份仓库必须是**私有仓库**（GitHub → New repository → Private）。

每个 agent 平台占一个一级目录，**当前安装本 Skill 的平台绑定其中唯一一个**，任务备份只写入它自己绑定的一级目录：

| Agent 平台 | 一级目录 |
|---|---|
| 爱思办公（Agnes Office） | `agnes-office` |
| WorkBuddy | `workbuddy` |
| 豆包 | `doubao` |
| Trae | `trae-code` |

```
D:\ai-backup\
├─ ai-workspace-backup\               ← 本地 git 仓库（备份目标，对应私有 GitHub 仓库）
│  ├─ .gitignore
│  ├─ agnes-office\                   ← 爱思办公的一级目录（平台绑定时写入这里）
│  ├─ workbuddy\                      ← WorkBuddy 的一级目录（平台绑定时写入这里）
│  ├─ doubao\                         ← 豆包的一级目录（平台绑定时写入这里）
│  └─ trae-code\                      ← Trae 的一级目录（平台绑定时写入这里）
└─ ai-workspace-backup-deploy\        ← 部署文件（MCP 服务 + 脚本 + 插件）
   ├─ mcp-git-backup\
   │  ├─ index.js                     ← MCP 服务（Node 编写）
   │  ├─ package.json
   │  ├─ mcp-launch.cmd               ← 确定性启动器（硬编码 Node v18+ 绝对路径）
   │  └─ node_modules\                ← npm install 生成
   ├─ push-all.ps1                   ← 批量 push 脚本（含代理兜底）
   ├─ agnes-office\
   │  ├─ plugin.yaml                 ← 爱思办公"手动备份"插件（只 commit，不 push）
   │  └─ push-plugin.yaml             ← 爱思办公"一键 push"插件
   └─ workbuddy\
      └─ SKILL.md                    ← WorkBuddy 侧的 Skill 文件
```

> Skill 执行时若发现某平台一级目录缺失，会自动创建并放 `.gitkeep`（git 追踪空目录），无需手工补建。

**创建命令**（PowerShell）：
```powershell
mkdir D:\ai-backup
cd D:\ai-backup
git init -b main ai-workspace-backup
cd ai-workspace-backup
mkdir agnes-office workbuddy doubao trae-code
# 每个目录放一个 .gitkeep（Git 追踪空目录）
foreach($d in @("agnes-office","workbuddy","doubao","trae-code")){
  New-Item -ItemType File "$d\.gitkeep" -Force | Out-Null
}
# .gitignore（拦截敏感/大文件）
@"
*.db
*.sqlite
*.sqlite3
node_modules/
.cache/
*.env
*.key
*.pem
*.png
*.jpg
*.pdf
*.xlsx
*.docx
*.pptx
*.mp4
*.zip
"@ | Set-Content ".gitignore" -Encoding UTF8
git add .
git commit -m "init: workspace backup skeleton"
# 配置远端（换成你的用户名和仓库名）
git remote add origin https://github.com/<你的用户名>/ai-workspace-backup.git
```

### 1.5 把 token 交给 Skill（一次配置）
```powershell
# 在 D:\ai-backup\ai-workspace-backup 目录下执行
# 将 <你的用户名> 与 <1.2 节仓库专属token> 替换为实际值
echo "protocol=https`nhost=github.com`nusername=<你的用户名>`npassword=<1.2节仓库专属token>" | Out-File -Encoding ASCII "$env:TEMP\cred.txt"
Get-Content "$env:TEMP\cred.txt" | git credential approve
Remove-Item "$env:TEMP\cred.txt" -Force
# 验证
git ls-remote origin
# 正常返回 refs 即成功（私有仓库不显示 "not found" 即认证 OK）
```
> token 只进凭据管理器，不落明文；之后 Skill 每次 push 自动走该 token 鉴权，无需再提供。

### 1.6 安装 MCP 服务（如需插件方式触发）
```powershell
cd D:\ai-backup\ai-workspace-backup-deploy\mcp-git-backup
npm install
# 自测（Node 必须 ≥ 18，用绝对路径避免 PATH 中的旧版）
& "E:\Program Files\nodejs\node.exe" index.js
# 看到 "mcp-git-backup server running on stdio" 即正常
```

### 1.7 安装 Skill（爱思办公 GUI 操作）
1. 打开爱思办公 → 左侧 **Skill** 列表
2. 点 **新建 / 导入 Skill**
3. 选择 `C:\Users\<你的用户名>\.agnes\skills\task-backup-github\SKILL.md` 导入
   - 或直接新建 Skill，名称填 `task-backup-github`，粘贴 `SKILL.md` 内容
4. 保存后，在任何任务对话框输入 **`$task-backup-github`** 即可调用

> 如果 Skill 不在列表中，也可在对话框直接输入 `备份当前任务到 GitHub`，Agent 会匹配到该 Skill。

## 2. 目录结构说明（Skill 运行后自动生成）

```
D:\ai-backup\ai-workspace-backup\
└─ <平台一级目录>\                    ← 当前 Skill 安装所在平台绑定的目录
   └─ <工作区名>\                     ← 当前 Agent 工具的工作区目录
      │                                    （取空间名，或工作区路径最后一段文件夹名）
      │                                    例：E:\me\agnes_WorkSpage → agnes_WorkSpage
      └─ task-<YYYYMMDD>-<任务名>\       ← 每个任务一个子目录
         ├─ index.md                      # 任务摘要 + 工作区信息 + 交付物索引
         ├─ conversation.md               # 完整对话日志（脱敏后）
         ├─ task_meta.json               # 结构化元数据（含 platform 字段）
         └─ outputs\                      # 文本类交付物（代码、md、json 等）
            ├─ xxx.py
            ├─ report.md
            └─ ...
```

**目录命名规则（三级）**
| 层级 | 规则 | 示例 |
|---|---|---|
| 一级目录 | 固定，按当前安装平台自动绑定（见 1.4 映射表） | `agnes-office`、`workbuddy`、`doubao`、`trae-code` |
| 二级目录（工作空间/项目名） | 空间名或工作区路径最后一段，空格→`_`，≤40 字符 | `agnes_WorkSpage` |
| 三级目录（任务） | `task-<YYYYMMDD>-<任务名>`（任务名保留中文/空格，仅剔除 7 个 Windows 非法字符）；每个新任务新建一个 | `task-20261005-AI 工作区自动备份部署` |

即：不同 agent 平台各占一个一级目录；当前任务备份到 `<平台目录>/<工作空间名>/<任务目录>` 下。

## 2.5 多平台适配说明

**同一份 SKILL.md，四个平台各装一份，平台目录自动隔离**：

| 平台 | 安装位置 | 绑定一级目录 |
|---|---|---|
| 爱思办公 | GUI 导入 Skill（`~\.agnes\skills\task-backup-github\SKILL.md`） | `agnes-office` |
| Trae | `~\.trae-cn\skills\task-backup-github\SKILL.md`（全局）或项目级 skills 目录 | `trae-code` |
| WorkBuddy | 工作区 skills 目录放 `SKILL.md`（见 `ai-workspace-backup-deploy\workbuddy\SKILL.md`） | `workbuddy` |
| 豆包 | 按其 agent/harness 的 Skill 导入机制装 `SKILL.md` | `doubao` |

**平台判定逻辑**（SKILL.md 内已实现，执行时依次尝试）：
1. 触发参数里带 `platform=<一级目录>` → 直接用
2. harness 可辨识特征（产品名/模型名/Skill 安装路径）→ 映射表自动匹配
3. 判不出来 → 询问用户，不猜测

**隔离保证**：A 平台的任务只会备份进 A 平台的一级目录，互不串扰；commit message 与 `task_meta.json` 均记录来源平台。

## 3. 使用方法

### 3.1 触发方式
在**任意任务**的对话框输入（任选其一）：
```
$task-backup-github
```
```
$task-backup-github 备份当前任务到 GitHub
```
```
备份当前任务到 GitHub
```
> 不需要任何额外参数，Agent 自动识别当前任务名称和工作区。

### 3.2 执行流程（全自动，一句话触发）
```
1. 判定当前平台 → 平台一级目录（映射表自动匹配，判不出则问用户；一级目录缺失则自动创建 + .gitkeep）
2. 识别工作区/空间名 + 任务名 → 生成目录 <平台一级目录>/<工作区>/task-YYYYMMDD-任务名/
3. 写入 index.md（任务摘要/来源平台/工作区/交付物清单）
4. 写入 conversation.md（完整对话日志，逐轮保留）
5. 写入 task_meta.json（结构化元数据，含 platform 字段）
6. 复制文本交付物到 outputs/
7. 脱敏：PAT/密钥/手机号/身份证/SMTP 授权码/隧道令牌 → [REDACTED]
8. git add + git commit（message 含平台一级目录）
9. git grep 脱敏自查（确认无敏感值进入 git 历史）
10. git push origin main
    ├─ 直连成功 → 报告 commit hash
    ├─ 直连失败 → 自动读系统代理（注册表 ProxyServer）
    │              无值则探测 1088/7890/7897/10809/1080 端口
    │              带代理重试（-c http.proxy / -c https.proxy，临时生效）
    └─ 全失败 → 本地 commit 已保存，提示双击桌面 ai-backup-push.bat 或等 03:00 计划任务补推
11. git ls-files 终态校验 + 输出最终报告（含平台一级目录）
```

### 3.3 最终报告示例
```
✅ 备份完成
─────────────────────────────
任务目录：D:\ai-backup\ai-workspace-backup\agnes-office\agnes_WorkSpage\task-20261009-XXX
本地 commit：a1b2c3d
push 结果：成功（代理 127.0.0.1:1088）
脱敏替换：1 处（GitHub PAT）
跳过文件：ai-workspace-backup-deploy.zip（二进制，已记录到 index.md）
```

### 3.4 补推（push 失败后手工操作）
- 双击桌面 **`ai-backup-push.bat`**（含直连→代理两级兜底，日志在 `D:\ai-backup\logs\backup-push.log`）
- 或等每晚 **03:00** 计划任务 `ai-workspace-backup-push` 自动补推

## 4. 故障排查

| 现象 | 原因 | 解决 |
|---|---|---|
| `git push` 报 443 连接超时 | 国内直连 GitHub 网络波动 | 自动走代理兜底；或手工双击 `ai-backup-push.bat` |
| `fatal: not a git repository` | 脚本工作目录不对 | 确认 `D:\ai-backup\ai-workspace-backup` 存在且已 `git init` |
| `node` 版本 < 18 报错 | PATH 中 `node` 是 AgnesCode 自带旧版 | 用 `E:\Program Files\nodejs\node.exe` 绝对路径，或改 mcp-launch.cmd |
| 中文文件出现乱码 | PS 5.1 `Set-Content -Encoding UTF8` 按 ANSI 读 | 改用 `[System.IO.File]::WriteAllText`（UTF8） |
| PAT 已失效 | Token 过期或被撤销 | 重新生成 PAT，执行 1.5 节配置命令更新凭据 |
| 对话被截断（只有摘要） | 爱思办公插件事件边界限制 | 在 Skill 里已内置：`conversation` 参数要求完整对话数组；若仍截断，需调整插件版本 |
